# HD-24 KPI Action Classifier — 개발/코딩일지

일자: 2026-09-14 KST

## 사용자 확정 요구사항
- 실적파일과 최종관리파일을 업로드하면 최종관리파일의 해당 월 Actual에 자동 매핑되어야 한다.
- 기존 안전반영 원칙(월헤더 동적탐색, KPI/단위 검증, 과거월 불일치 차단, 미래월 오염 차단, 중복 KPI×월 차단, 반영 후 재검증)은 유지한다.
- 자동반영 완료 후 최종관리파일에 담당자 입력용 `미달사유 / 만회계획` 열을 생성한다.
- KPI 지표명 원문 문자열은 자동매핑 키이므로 변경하지 않는다.
- KPI명 셀은 서식/색상 등 시각요소로 상태를 구분한다.
- 상태는 최소 다음을 구분한다: 당월 목표미달, 3개월 이상 지속악화, 6개월 이상 장기 지속악화, 일시적 악화, 정상/개선.
- 당월 목표미달과 장기악화는 배타적 판정이 아니라 동시에 표기할 수 있어야 한다.
- 상향지표/하향지표 방향성을 고려하지 않은 단순 증감판정은 금지한다.
- 향후 HTML 분석메일은 자동분석 결과와 담당자 입력 미달사유/만회계획을 함께 사용한다.

## 이번 구현
### 1. 신규 분류 모듈
- 파일: `kpi-action-classifier.js`
- 목적: 기존 `safe-kpi-mapping.js`의 안전반영 로직과 후속조치 분석 로직을 분리하여 회귀위험을 낮춘다.
- 구현 함수:
  - `dirToken(direction)`: 상향/하향 방향 표준화
  - `isMiss(actual,target,direction)`: 당월 목표미달 판정
  - `worsened(prev,current,direction)`: 월간 악화 판정
  - `consecutiveWorsening(values,direction)`: 최신월 기준 연속악화 개월 계산
  - `classifyKpi(...)`: 미달 + 3개월/6개월/일시악화 복합 판정
  - `visualToken(result)`: KPI명 셀 시각구분용 토큰
  - `actionPrompt(result)`: 담당자 입력 기본 문구

### 2. 판정 우선순위
- 6개월 이상 장기 지속 악화: 최우선 경고
- 3개월 이상 지속 악화
- 당월 목표미달
- 일시적 악화
- 정상/개선
- 복합상태는 label에 동시 표시한다. 예: `당월 목표미달 + 6개월 이상 장기 지속 악화`.

### 3. 담당자 입력 기본 문구
이상 KPI에 한해 다음 입력 프롬프트를 생성하도록 정의:
- 미달사유
- 근본원인
- 만회계획
- 완료예정일
- 차월 예상실적

정상/개선 KPI에는 입력 프롬프트를 생성하지 않는다.

### 4. 실제 최종관리파일 구조 점검
Library에서 접근 가능한 기존 최종관리파일 구조를 실제 확인했다.
- 대상 시트: `인도법인 KPI(26년 보고용)`, `브라질법인 KPI(26년 보고용)`
- 헤더행: 4행
- KPI명: M열 (`표준 성과지표(KPIs)`)
- 목표: Y열
- 단위: Z열
- 월실적: AA~AL열 (1월~12월)
- AM열은 대부분 비어 있으나 1행에 계산값이 있으므로 덮어쓰기 금지
- 후속조치 신규 열은 기존 데이터 뒤인 AN열(40번째 열)부터 생성하는 것이 안전함
- 단, 런타임에서는 M/Y/AA~AL을 무조건 하드코딩하지 않고 헤더명을 재탐색하도록 설계함

### 5. 신규 Workbook 후처리 모듈
- 파일: `kpi-action-workbook.js`
- 주요 안전규칙:
  - KPI 헤더 `표준 성과지표(KPIs)` 재탐색
  - `목표/단위` 헤더 재탐색
  - 1~12월 헤더 전수검증 및 중복월 차단
  - 기존 마지막 사용열 이후에 `미달사유 / 만회계획` 열 생성
  - KPI명 문자열은 수정하지 않고 fill/font 서식만 변경
  - 이상 KPI에만 담당자 입력 프롬프트 생성
  - 안전매핑 결과의 `masterRow` 및 `direction`을 그대로 사용
  - 중복 masterRow 발생 시 후속조치 생성 중단
  - KPI명 원문 변경 여부를 처리 후 재검증
